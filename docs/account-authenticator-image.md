# Изображение аутентификатора в аккаунте

Рядом с полем «Код аутентификатора» можно прикрепить один PNG, JPEG или WebP
до 1 МБ и размером не больше 4096 × 4096. QR может заменить текстовый код при
создании аккаунта; остальные обязательные поля остаются прежними.

Выбор файла показывает локальную миниатюру. Прикрепление, замена и удаление
сохраняются общей кнопкой карточки. Отмена редактирования восстанавливает прежнее
изображение, закрытие с несохранённой картинкой требует обычного подтверждения.
Во время чтения файла сохранение заблокировано. Ошибка файла не удаляет прежнюю
картинку. В просмотре миниатюра открывает увеличенное изображение в нативном
диалоге; Escape и кнопка «Закрыть» возвращают в карточку.

## Хранение и API

- Используется новый ключ `authenticator_image` в существующей `account_secrets`.
  Значение — data URL в штатном base64-представлении секретов. Это не отдельное
  шифрование. Схема БД не меняется, SQL-миграция не нужна.
- `GET /accounts/{id}/authenticator-image` возвращает `{image, version}` и
  `Cache-Control: no-store`. Роли совпадают с доступом к секретам: owner, admin,
  manager, operator. Публичной ссылки на файл нет.
- В `PUT /accounts/{id}/secrets` добавлены необязательные `authenticator_image`
  и `expected_authenticator_image_version`. Отсутствие изображения в запросе
  оставляет его прежним; пустая строка означает удаление. Для первого прикрепления
  исходная версия — пустая строка.
- Под блокировкой аккаунта сверяется SHA256 исходного изображения. Устаревшая
  замена или удаление получает 409. Изображение и остальные секреты сохраняются
  в одной транзакции. Прямые старые операции с этим ключом заблокированы.
- Браузер проверяет размер, MIME и декодирование. API отдельно проверяет размер
  данных, base64, сигнатуру формата и размеры в заголовке. SVG и внешние URL
  не принимаются. Файл не преобразуется и QR автоматически не распознаётся.
- Изображение исключено из обычного и пакетного списка секретов. Оно загружается
  отдельно только при открытии/обновлении карточки аккаунта, не попадает в таблицы
  сделок и Excel-экспорт. Штатная резервная копия БД включает этот секрет.

Изменения требуют совместной поставки API и web. Данные production для разработки
и проверок не использовались и не менялись.

## Ручная проверка

После выкладки проверить на тестовом аккаунте:

1. Прикрепить QR, сохранить и повторно открыть аккаунт: миниатюра сохранилась.
2. Открыть увеличенное изображение; закрыть кнопкой и Escape.
3. Заменить/удалить изображение и отменить правки: прежняя картинка остаётся.
   Затем повторить с сохранением.
4. Проверить широкий экран и ширину меньше 600 px: блок переносится под код,
   длинные/высокие картинки не растягивают модалку, соседние поля доступны.
5. В двух карточках заменить один QR: второе сохранение должно сообщить конфликт.
6. Проверить неправильный формат и файл больше 1 МБ: прежний QR не меняется.

Ручной smoke WorkView выполняет пользователь; агент браузер не открывал.
