## Поведение

- Резерв получает постоянный ID и неизменяемый ключ. Замена значения в редакторе
  создаёт другой резерв, перестановка сохраняет принадлежность прежней сделке.
- Копирование, импорт, редактирование и назначение защищены блокировкой аккаунта;
  устаревший снимок редактора и занятый явно выбранный резерв возвращают конфликт.
- При переходе сделки в завершённую удаляются значения её резервов, включая
  прежние выдачи из нового журнала. Если код нужен другой активной сделке,
  очистка откладывается. Метаданные и журнал остаются. В завершённой сделке
  отображается только «выдан», без копирования и пояснений.
- В блоке данных аккаунта сделки есть «Открыть аккаунт». Карточка загружается
  по новому GET `/accounts/{account_id}` вместе со свежими секретами. Несохранённые
  правки требуют существующего подтверждения закрытия; ошибка загрузки сохраняет сделку.
- Старый одиночный API секретов возвращает новый ключ и корректно обрабатывает
  пробелы по краям значения.

## Ручные кейсы для пользователя

Проверять на отдельном тестовом аккаунте и тестовых сделках после обновления страницы.

1. Открыть аккаунт из новой, рабочей и завершённой сделки: правильный аккаунт,
   актуальные резервы, статус и даты деактивации. Изменить деактивацию и открыть снова.
2. Внести несохранённую правку сделки и нажать переход. Отмена подтверждения должна
   оставить форму и текст; подтверждение — открыть аккаунт. Ошибка сети оставляет сделку.
3. Назначить/скопировать резерв A в сделке, затем заменить его в аккаунте на B.
   B свободен, старая сделка сохраняет A. Перестановка и удаление соседних строк
   не передают чужому коду отметку «использован».
4. В двух редакторах аккаунта изменить список: второй устаревший снимок должен
   получить конфликт. После повторного открытия видны изменения первого.
5. Два сотрудника одновременно копируют один резерв, либо две сделки пытаются его
   сохранить: успешная выдача/привязка только одна, второй запрос получает конфликт.
6. Завершить сделку: в поле только «выдан», код не копируется; из списка аккаунта
   исчезает её резерв, другие коды остаются. Повторное сохранение не списывает следующий.
7. Вернуть завершённую сделку в работу: удалённый код не восстанавливается;
   новый резерв выбирается явно. Смена резерва до завершения очищает также прежние
   выдачи этой сделки, зарегистрированные новым журналом.
8. Отменить/удалить тестовый черновик: не скопированный резерв освобождается,
   скопированный остаётся занятым. Проверить, что обычное открытие сделки без
   сохранения не назначает новый код.
9. На тестовом аккаунте проверить импорт заменённых кодов и последующий экспорт:
   старые связи сохраняются, новые коды доступны. Текущий формат поддерживает десять
   резервов; расширение формата остаётся в TODO.

На копии production найдены 32 группы старых дублей значений и 24 ссылки без значения;
неканонических ключей нет. Дубли заблокированы для новой выдачи и требуют отдельного
разбора. Релиз не восстанавливает значения, перезаписанные до появления постоянных ID.

Этот отчёт фиксируется отдельным коммитом после релиза и не меняет сборку приложения.
