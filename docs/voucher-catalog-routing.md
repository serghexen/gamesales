# Приоритет поставщиков каталога ваучеров

Настройки относятся к собственному номиналу (`catalog_nominal_id`), а не ко всей услуге.
Один номинал объединяет несколько предложений разных поставщиков. Карточка позволяет
переставлять предложения и отключать их участие в будущей автовыдаче. Селлер пока эти настройки
не использует; покупки и переход на ручную выдачу остаются без изменений.

На основном экране услуга содержит компактные свёрнутые строки номиналов. Строка
показывает количество поставщиков и снимки первого включённого предложения по приоритету;
цены не сравниваются для выбора сводки, остатки разных поставщиков не суммируются.
Стрелка раскрывает поставщиков только выбранного номинала. Название открывает карточку.
Если все предложения выключены, сводка отмечает это и показывает «—» вместо цены и остатка;
сохранённые снимки всех предложений доступны в раскрытых деталях.

## Хранение и чтение

- `voucher_catalog_offers.fulfillment_priority` — положительное число, меньший номер идёт раньше.
- `fulfillment_enabled` — участие в будущей выдаче. По умолчанию `true`.
- `active` по-прежнему означает существующую связку. Отключение выдачи не отвязывает поставщика:
  цена и остаток продолжают обновляться, предложение остаётся видимым в каталоге.
- `voucher_catalog_nominals.fulfillment_revision` — версия настроек и состава связок.

`GET /voucher-catalog` возвращает оба поля предложения и версию номинала. Предложения
внутри номинала идут по `fulfillment_priority`, затем по `offer_id`. Отключённые предложения
сохраняют свою позицию. Пропуски номеров после отвязки допустимы; они не меняют порядок.
При сохранении полного порядка номера нормализуются от 1.

Новая связка добавляется в конец, включённой. Повторное сохранение уже активной связки
сохраняет её приоритет и переключатель. Повторная привязка отвязанного предложения
возвращает его в конец и включает в выдачу. Изменение имени не должно само по себе менять порядок.

## Атомарное сохранение

В существующий `POST /voucher-catalog/items/{item_id}/nominals` добавлено необязательное поле
`routing` у редактируемого номинала:

```json
{
  "nominals": [{
    "catalog_nominal_id": 11,
    "name": "1000 TRY",
    "routing": {
      "revision": 3,
      "offers": [
        {"offer_id": 20, "enabled": true},
        {"offer_id": 10, "enabled": false}
      ]
    }
  }]
}
```

Порядок массива задаёт приоритет. Нужно передавать все активные связки этого номинала,
включая выключенные из автовыдачи. Пустой массив допустим только при отсутствии связок.
Если `routing` отсутствует, текущий порядок сохраняется. Новая `binding`, переданная
вместе с `routing`, добавляется после проверки и сохранения существующего порядка.

Имя, приоритеты, переключатели и новая связка сохраняются в одной транзакции. Все изменения
состава связок используют блокировку родительской услуги и увеличивают версию номинала.
Устаревшая версия, неполный набор или чужие ID дают `409`; дубли ID — `422`.
Ошибка откатывает всю операцию. Редактировать могут только `admin`/`owner` с правом раздела.
Перестановка и переключатели не обращаются к API поставщика.

## Удаление номинала

`DELETE /voucher-catalog/items/{item_id}/nominals/{catalog_nominal_id}` удаляет собственный
номинал и все его предложения (включая ранее отвязанные) одной транзакцией. Родительская
услуга и остальные номиналы сохраняются. В интерфейсе действие доступно через корзину
рядом с названием или из карточки, с отдельным подтверждением. «Отвязать» по-прежнему
касается только одного поставщика.

Удаление разрешено редакторам каталога. Чужой или отсутствующий ID возвращает `404`;
запрет внешнего ключа — `409` с полным откатом операции. Повторно создать номинал с тем
же именем и соответствиями можно; новый номинал получает новый ID. При подключении
селлера его ссылки на номиналы и предложения должны иметь внешние ключи, запрещающие
удаление используемых записей.

## Контракт будущей выдачи

Селлер должен брать активные включённые предложения по сохранённому порядку. Цена не
переставляет поставщиков автоматически. Сохранённый остаток является снимком, а не резервом.
Переход к следующему возможен при отсутствии товара или подтверждённом отказе без покупки.
Таймаут покупки требует проверки её результата у того же поставщика, а не немедленного
повтора у другого. Когда варианты исчерпаны, сохраняется существующий сценарий ручной выдачи.
Этот исполнитель и привязка товаров селлера к собственному номиналу реализуются отдельно.

## Удаление услуги

Корзина в строке услуги и действие «Удалить услугу» в её карточке открывают подтверждение
с сохранённым названием и количеством номиналов. `DELETE /voucher-catalog/items/{item_id}`
доступен администраторам и владельцам с правом просмотра каталога. Под блокировкой услуги
одна транзакция удаляет все предложения (включая отвязанные), затем собственные номиналы
и саму услугу. При конфликте внешнего ключа возвращается 409 и все изменения откатываются.
Другие услуги и каталог поставщика не затрагиваются.
